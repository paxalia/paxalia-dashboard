# Paxalia Dashboard v5.0.0

## Release focus

**Paxalia Dashboard v5.0.0 — Operational Infrastructure**

v5.0.0 is the current major release. Its purpose is to extend the mature v4 operational platform into practical server-operation workflows that historically required administrators to leave the dashboard and use SSH, SCP, manual filesystem commands, external uptime tools, or ad-hoc cleanup scripts.

## Operational architecture

The v5 release is organized around connected capabilities:

```text
v4 foundation
```

These systems reuse the existing authentication, permissions, logging, notifications, backups, uploads, server monitoring, and uptime architecture.

## Server Files

The current Server Files subsystem provides controlled filesystem operations rather than a shell. It supports bounded directory listing, previews, downloads, uploads, directory creation, rename, move, copy, delete, and operation history.

The security boundary is explicit:

```text
browser root ID + relative path
        ↓
normalization
        ↓
canonical path checks
        ↓
allowed-root policy
        ↓
denied-path policy
        ↓
symlink policy
        ↓
capability check
        ↓
optional recent re-authentication
        ↓
operation + audit history
```

Roots must be explicitly configured. The package defaults to the feature being disabled and to an empty allowed-root list; it never invents filesystem root access.

## Transfer Center

The Transfer Center extends the existing upload/chunk infrastructure into persistent send/receive operations with:

- chunked transfer
- resumability
- bounded retries
- pause/cancel/retry lifecycle controls
- explicit verification state
- SHA-256 integrity verification
- fixed exchange binding
- private resumable staging
- bounded concurrency
- safe collision handling
- transfer history

The transfer state model is explicit:

```text
QUEUED
PREPARING
TRANSFERRING
PAUSED
INTERRUPTED
VERIFYING
COMPLETED
FAILED
CANCELLED
EXPIRED
```

The browser cannot choose an arbitrary server filesystem path. Transfer destinations are bound to the server-side exchange policy.

## Availability

v5 extends the existing uptime subsystem rather than creating a second monitor engine. Current monitors support:

- server
- website
- API
- endpoint

and:

- GET
- HEAD
- POST
- expected status validation
- expected content-type validation
- bounded response bodies
- bounded POST request bodies
- response assertions
- safe redirect handling
- configurable timeout and interval
- consecutive failure/recovery thresholds
- UP / DOWN / UNKNOWN observations
- transition-based incidents

The implementation intentionally distinguishes target failure from uncertainty in the monitoring system.

## Resource and retention controls

v5 strengthens resource governance for persistent operational data:

- maximum log record count

- severity-specific retention
- category-specific retention
- protected critical/security records
- bounded realtime event display and buffers
- realtime batching
- automatic live-stream backpressure thresholds
- transfer history limits
- availability history limits
- server metric limits
- incremental cleanup commands
- bounded global maintenance budgets

## v5 security principles

The operational surface remains inside the v4 administrator security boundary:

```text
Password
↓
Mandatory 2FA / recovery
↓
Authorized WebAuthn device
↓
Paxalia administrator session
```

Additional v5 rules include:

- no arbitrary shell or command execution
- no unrestricted filesystem root by default
- no browser-trusted raw filesystem paths
- explicit permissions for operational actions
- sensitive-path controls
- bounded upload/download/preview operations
- no-overwrite behavior for protected transfers
- server-side integrity verification
- auditability of sensitive operations

## Release principle

The goal of v5.0.0 is not simply a larger dashboard. It is to reduce the number of ordinary production operations that require leaving Paxalia Dashboard.
