# Paxalia Dashboard v4.0.0

## Release focus

**Paxalia Dashboard v4.0.0 — Platform foundation: persistent observability, Paxalia Admin, and administrator security**

v4.0.0 is the major architectural foundation on which the current v5 release is built.

## Repository milestones

The supplied history records three major feature lines before the v4.0.0 tag:

- `7411bf4` / `d72cb64` — persistent structured observability and logging dashboard
- `fd11c20` / `1dbdc69` — Paxalia Admin and model-aware package management
- `476eab1` / `533eff8` — complete Paxalia authentication and administrator security

## Persistent observability

The v4 logging line established a database-backed structured logging system around ordinary Django/Python execution. The architecture includes:

```text
Python / Django logging
+
Paxalia logging API
        ↓
normalization
        ↓
request/runtime context
        ↓
redaction
        ↓
fingerprinting/grouping
        ↓
bounded persistence
```

This became the basis for the current Logs Center and the resource/retention controls later strengthened in v5.

## Paxalia Admin

The v4 Admin line established a generic Django-native administrative workspace that builds on the existing Django Admin registry rather than replacing it.

The architecture is:

```text
Django Admin registry
        ↓
Paxalia Admin registry / adapters
        ↓
permissions + capabilities
        ↓
queries / services / forms
        ↓
Paxalia Admin UI
```

The system was designed to support dynamic model discovery, CRUD, relationships, inlines, actions, history, sensitive-field protection, and localization-aware administration while retaining Django Admin as the fallback authority.

## Model-aware package operations

v4 introduced the model-aware `.paxalia` package workflow, including logical serialization, relationship preservation, identity-aware import/export, integrity protection, encrypted/protected package handling, conflict strategies, and recovery-oriented import behavior.

## Administrator security boundary

The v4 authentication line established the mandatory layered administrator access model:

```text
Password
   ↓
Mandatory TOTP / recovery
   ↓
Authorized WebAuthn device
   ↓
Paxalia administrator session
```

Defense-in-depth controls include rate limits, CSRF protection, isolated session state, dedicated administrator cookies, a deployment-specific dashboard path, sensitive-data protection, no-store responses, and security/audit visibility.

## Foundation preserved by v5

v5 is explicitly built on this v4 architecture. It must not create duplicate logging, administration, uptime, authentication, notification, package, or backup systems when the existing subsystem can be extended.
